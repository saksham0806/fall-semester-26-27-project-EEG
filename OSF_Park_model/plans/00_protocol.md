# Plan 00 — held-out test set

**Do this before any of 01–03.** It is the cheapest plan here and the only one that changes
what every subsequent number means.

## Why

Eleven models have now been evaluated on the same 15 folds. The reported best, 0.4299, is the
maximum of 11 correlated estimates on one resampling of 527 subjects — it is optimistically
biased before a single new architecture is added. Plans 01–03 propose roughly a dozen more
configurations. Without a held-out set, the sequence terminates in a 0.48 that does not
replicate, and there is no way to tell that from a 0.48 that does.

This repo has the failure on record in a different costume: `CLAUDE.md` documents that a
random split reports 0.9393 on the all3 task where a grouped split reports 0.6256. The
mechanism differs — leakage there, selection here — but the outcome is identical: a number
that cannot survive contact with new data, produced by a one-line choice nobody flags.

## What

Split once, at the top, and freeze it.

```
OSF_Park_model/splits/holdout_4class.json    {"dev": [...], "test": [...]}   n=527
OSF_Park_model/splits/holdout_binary.json                                     n=292
```

- **20% stratified test**, `random_state=1234`, stratified on the 4-class label (not on
  `main.disorder`, and not on `specific.disorder`).
- **80% dev.** All cross-validation, all model selection, all hyperparameter search, all
  feature engineering happens here. `splits(y)` continues to operate, but on dev indices only.
- Generated by a standalone `OSF_Park_model/make_holdout.py` that **refuses to overwrite an
  existing file** unless `--force` is passed. The refusal is the whole point: a regenerated
  split is a silently different experiment.
- Committed to git. The JSON is ~4 KB and is the provenance for every number that follows.

Stratified sizes, 4-class: test ≈ 106 (healthy 19 / depression 40 / anxiety 21 / stress 26),
dev ≈ 421.

## The rule

**The test set is scored once, at the end, by one model per plan.** Not per configuration —
per plan. Scoring it twice and reporting the better one reinstates exactly the bias this
removes.

Operationally, that means test-set evaluation lives in its own script that a person runs
deliberately:

```bash
.venv/bin/python -u -m OSF_Park_model.final_test --plan 01 --model <label>
```

`final_test.py` appends — never overwrites — to `Results/OSF_Park/FINAL.md`, recording the
date, the plan, the model label, the dev score, the test score and the config hash. An
append-only log makes a second peek visible rather than deniable.

**`run.py` must never read the test indices.** Add an assertion to that effect in `evaluate()`
so the guarantee is enforced by code rather than by discipline:

```python
assert not (set(te) & TEST_IDX), "test-set indices leaked into a CV fold"
```

## Cost and honesty about it

Dev drops from 527 to ~421 subjects, and the smallest class from 93 healthy to ~74. That is a
real loss on an already small cohort, and it will make dev-CV noisier. It is worth paying
because the alternative is not a better estimate — it is an unfalsifiable one.

The test set at n≈106 gives a 4-class accuracy standard error of roughly ±0.048. That is wide.
It is wide enough to detect the difference between "EEG adds nothing" and "EEG adds 0.10", and
too wide to resolve 0.43 from 0.46. Say so in the write-up rather than reporting the test
figure to four decimals as though it were precise.

## Verification

- `make_holdout.py` run twice without `--force` leaves the file byte-identical.
- Dev and test index sets are disjoint and union to the full cohort.
- Class proportions match between dev and test to within 2 percentage points.
- The assertion in `evaluate()` fires if test indices are injected deliberately — write that
  as a test, do not assume it works.
